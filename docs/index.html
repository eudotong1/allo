Allo Router

Allo Router plans which AI plan should take which job before limits reset. It can then run the jobs, but only the plan you reviewed, and only when you say so.

If you pay for more than one AI plan, each one has its own limit and its own reset. Capacity on one can expire while another has already run out. You list your plans, what is left, when each resets, and your jobs. Allo Router ranks the plans by how much is left against how soon each resets, and tells you where each job should go first: the plan closest to expiring that can still take it.

It reads two files you keep. One is your plans: what is left, when each resets, and which kinds of data each may touch. The other is your jobs. You type the readings in. A reading older than 24 hours is flagged.

The planner never logs in, sends anything or makes a network request. Starting jobs is a separate step, allo-router run, which runs the CLI you set up for each plan, such as claude -p or codex exec. Allo Router stores no API keys; the CLI should already be logged in.

New in 0.2.0

  • An executor. allo-router run turns the plan into jobs and runs each through its plan's backend: shell (a command list, never passed through a shell), dry-run, or your own. It asks before each job, logs every run to runs.jsonl and keeps each job's output in runs/. It never edits your plans or jobs files.
  • Preview by default. allo-router run on its own starts nothing. It shows every job, its plan and the exact command, and saves that as plan.json.
  • Runs exactly the plan you reviewed. allo-router run --plan plan.json --execute runs only that saved plan. It refuses, and starts nothing, if the file was edited, is older than 60 minutes (the default), your readings or config changed, or any job would now come out differently. --execute without a saved plan is refused.
  • Safe starter config. Every starter plan is on the dry-run backend, so a first --execute on a new install cannot start a real agent. The dry run shows the command it would run.

Also new: allo-router --version, a guard against running a finished job twice, and API jobs that stay unassigned when the credit pool cannot take them, instead of falling back to a subscription. Full list in the changelog.

Quickstart

Needs Python 3.9 or newer. No dependencies. Install with pip install . from a checkout of the repository (not on PyPI yet), or run python3 allo.py directly.

mkdir my-router && cd my-router
allo-router init                   # writes pools.json and tasks.json
allo-router                        # prints the plan
allo-router set chatgpt pct=55     # record a fresh reading
allo-router run                    # preview: the exact command each job would run; saves plan.json
allo-router run --plan plan.json --execute   # runs exactly that plan, asking before each job

Without installing, replace allo-router with python3 /path/to/allo.py. The starter files describe four example plans with made-up readings. Replace them with yours before trusting anything.

To let a plan start real jobs, check the command its dry run shows against the CLI you have installed, then change that plan's "backend" from "dry-run" to "shell" in pools.json. Do one plan at a time.

"run": {"backend": "shell", "command": ["codex", "exec", "{prompt}"]}
